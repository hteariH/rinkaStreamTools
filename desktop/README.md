# Приложение

Окно панели управления и оверлей поверх игры в одном приложении — чтобы запуск был
одним ярлыком, а не командой в терминале.

Внутри три вещи:

- **окно панели** — обычное окно с той же панелью, что открывается в браузере;
- **окно оверлея** — прозрачное поверх всех остальных, со скримерами на своём экране
  (Browser Source в OBS видят только зрители); мышь и клавиатура проходят насквозь;
- **сервер** — дочерний процесс, поднимается сам и гаснет вместе с приложением.

Своего фронтенда у приложения нет: оба окна показывают страницы того же локального
сервера, что и OBS. Внутри системный WebView2, поэтому приложение весит около 6 МБ и
своего браузера не тащит.

## Сборка

```bash
cargo build --release
```

Дальше `npm run build:exe` в корне проекта подберёт готовый бинарник и разложит папку
для раздачи — см. README проекта.

## Запуск при разработке

Сервер рядом с бинарником при разработке не лежит, поэтому приложение его не поднимает,
а подключается к уже запущенному. В одном терминале:

```bash
npm start
```

В другом:

```bash
cargo run
```

Если сервер живёт на другом порту или на другой машине в локальной сети:

```powershell
$env:RINKA_HOST='http://192.168.1.50:3777'; cargo run
```

## Управление

| Где | Что |
|---|---|
| Крестик на окне панели | прячет её в трей, приложение и сервер продолжают работать |
| Трей → Панель управления | вернуть окно панели |
| Трей → Скримеры поверх игры | включить/выключить окно оверлея (галочка) |
| Трей → Переподключиться | перезагрузить обе страницы, если сеть отваливалась надолго |
| Трей → Выход | закрыть приложение вместе с сервером |

Крестик намеренно не закрывает приложение: иначе стример посреди эфира уронил бы вместе
с окном и сервер, а с ним все оверлеи в OBS.

## Как оно находит сервер

1. `RINKA_HOST`, если задана, — тогда сервер не запускается, приложение просто смотрит
   по адресу.
2. Иначе ищет `server/rinkaStreamTools-server.exe` рядом с собой (так разложено в
   собранной папке), затем просто рядом.
3. Порт берёт из `config.json` рядом с найденным сервером — он мог быть изменён в
   панели. Конфига нет — 3777.
4. Не нашёл сервер — считает, что тот запущен снаружи, и ждёт порт.

Перед открытием окон приложение ждёт, пока порт ответит (до 25 секунд), иначе WebView2
показал бы свою страницу ошибки вместо панели.

## Вывод сервера

Консоли у приложения нет, поэтому вывод сервера пишется в `server.log` рядом с ним —
туда и надо смотреть, если что-то не поднялось.

Штатно сервер гасится вместе с приложением. Если приложение сняли через диспетчер задач,
сервер это заметит сам (ему передан pid родителя) и выйдет в течение нескольких секунд —
иначе он остался бы висеть и держать порт.

## Что важно знать про оверлей

- **Игра должна идти в оконном или безрамочном режиме.** Эксклюзивный полноэкранный
  режим перекрывает вообще всё, включая это окно — ограничение Windows, обойти нельзя.
- Звук идёт со стороны своего компьютера. Если скример должен быть слышен и зрителям,
  добавь в OBS захват звука рабочего стола.
- Прозрачность скримеров задаётся ползунком в панели и применяется без перезапуска.

## Требования к сборочной машине

Rust и MSVC Build Tools с Windows SDK. На машине, где приложение просто запускается,
ставить ничего не нужно: WebView2 входит в Windows 11, а в Windows 10 обычно приезжает
с обновлениями.
